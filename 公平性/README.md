## 个人 PyTorch 练习

`mlp_torch_11f.py` 参考 `google_fairness_baseline.py`，使用 PyTorch 实现 `11 → 64 → 32 → 1` 的二分类网络。文件名中的 `mlp` 表示多层感知机，`torch` 表示 PyTorch，`11f` 表示 11 个输入特征。

代码按标签分层划分 80% 训练集、10% 验证集和 10% 测试集，两次划分均使用 `random_state=42`；验证集、测试集复用训练集的均值和标准差。网络隐藏层使用 ReLU，末层输出 logits，不加 Sigmoid；BCE with Logits 内部处理 Sigmoid。训练采用 Adam（学习率 `0.001`）、批大小 `100` 和 `10` 轮训练，每轮打印验证集 Loss、Accuracy 和 AUC。

当前基础文件的训练、ONNX 导出和 `.pt` 保存调用均已启用；直接运行会重新训练并覆盖基础模型。末尾的 ONNX 预测示例已注释。虽然创建了测试集 DataLoader，当前文件没有执行整体测试评估；早期实验的测试结果为 Loss `0.4109`、Accuracy `0.8046`、AUC `0.8828`。性别分组评估已移到独立文件，个人 PyTorch 流程目前只打印结果，没有生成可视化报告。

训练代码优先使用 CUDA，CUDA 不可用时回退到 CPU；模型、数据和评估指标放在同一设备上。已在 Windows、NVIDIA GeForce RTX 4060 Laptop GPU 上完成训练。

ONNX 预测设备由 ONNX Runtime 的 `providers` 单独指定，与 PyTorch 训练设备分开配置。当前加载代码使用 `CPUExecutionProvider` 在 CPU 上预测；如改用 `CUDAExecutionProvider`，需要 ONNX Runtime 的对应 GPU 依赖，当前 Windows 环境曾遇到 CUDA 执行提供程序加载失败的问题。

开发时使用本机 Anaconda 的 `machine_learning` 环境，该环境不包含在仓库中。运行个人 PyTorch 练习需自行准备兼容的 Python 环境及 pandas、PyTorch、TorchMetrics、scikit-learn 和 ONNX Runtime 等依赖；重新导出 ONNX 还需相应的导出依赖。本地数据集统一放在根目录 `data` 文件夹。

### 文件为什么分开，以及模型如何衔接

| 文件 | 输入 | 执行内容与输出 | 单独保留的原因 |
| --- | --- | --- | --- |
| `mlp_torch_11f.py` | CSV | 从头训练，保存 `models/mlp_torch_11f.pt` 和同名 `.onnx` | 保留基础模型作为比较起点 |
| `finetune_torch_11f.py` | CSV、基础 `.pt` | 恢复模型和 Adam 状态，继续训练，保存 `mlp_torch_11f_weighted.pt/.onnx` | 将样本加权实验与首次训练分开 |
| `mmd_torch_11f.py` | CSV、加权 `.pt` | 恢复模型和 Adam 状态，进行 MMD 微调，保存 `mmd_torch_11f.pt/.onnx` | 将另一种损失函数实验单独保留 |
| `eval_torch_11f.py` | CSV、选定的 `.onnx` | 不训练，打印男女 Accuracy、Precision、Recall、FPR | 更换模型路径即可使用相同方式比较模型 |

三个训练文件使用相同网络结构。`.pt` 保存 `model_state_dict`、`optimizer_state_dict`、训练集 `mean/std`、`feature_names` 和本次 `epochs`；它是本练习继续训练使用的检查点，需要在代码里先构造相同网络再加载参数。微调文件恢复保存的标准化参数，但输入列顺序仍由代码明确指定；加载优化器状态也会恢复其中的学习率。当前保存的是最后一轮模型，不是自动挑选的最佳轮次，检查点没有保存每次实验的权重配置。

ONNX 用于本练习的预测流程，不用于继续训练。三个 ONNX 都以单条样本导出，输入名称为 `features`、形状为 `(1, 11)`，输出名称为 `logits`。名称是导出时起的接口名。输入标准化在模型外完成，输出经 Sigmoid 转为高收入预测概率，再以 `>= 0.5` 判为高收入；这不代表预测一定正确，还需和真实标签比较。单条特征原本为 `(11,)`，需用 `unsqueeze(0)` 补上批次维度；固定批大小为 1 时，当前脚本用循环预测多人。

### 数据划分与公平性评估

训练文件保留 80% / 10% / 10% 划分：训练集更新参数，验证集观察表现，测试集用于最终评估。验证 DataLoader 使用 `shuffle=False`，便于保持顺序；整体指标的正确计算不依赖打乱验证数据。

当前 `eval_torch_11f.py` 只执行第一次 80% / 20% 划分，将剩余 20% 全部作为分组分析数据，也就是原来的验证集与测试集合并。固定种子、原始数据、行顺序和划分参数一致时，可以重建相同划分。评估文件重新计算原 80% 训练集的均值、标准差，然后处理剩余数据，不能用评估集自己的统计量代替训练集统计量。

这 20% 已用于反复比较模型，是本练习的探索性分析集，不能再当作从未参与方案选择的独立最终测试集。公平性需要足够的各组样本，最初 50 条只用于检查逻辑；当前已取消 50 条限制，遍历整个 20%。逐条 ONNX 推理以及设备间数据传输会使评估较慢。

分组使用未标准化的原始 `SEX`（1 男、2 女），预测和标签保持同一行对应。每组分别统计：TP 为真实高收入且预测高收入，TN 为真实非高收入且预测非高收入，FP 为误报高收入，FN 为漏判高收入。指标的分母来自该组，而不是整个训练集：

```text
Accuracy  = (TP + TN) / (TP + TN + FP + FN)
Precision = TP / (TP + FP)
Recall    = TP / (TP + FN)
FPR       = FP / (FP + TN)
```

这里检查的是不同性别的预测错误是否存在差异，不是直接判断现实中的男女收入是否公平，也不能仅凭差距证明歧视。即使删除性别输入，其他特征仍可能与性别相关，分组错误率也未必相同。当前关注点是女性高收入者是否更容易被漏判，同时观察降低漏判是否带来更多误报。

### 样本加权和 MMD 分别做了什么

`finetune_torch_11f.py` 对真实高收入女性使用较大的样本权重，其余样本为 1。先计算每条样本 BCE，再乘权重取平均。已尝试 1.5 和 1.6，当前代码为 1.6；它们是实验参数，不是固定标准，也不是 MinDiff。加权让训练更重视这些样本的分类错误，可能提高召回率，同时增加假阳性率。

`mmd_torch_11f.py` 当前从加权模型继续训练，但这一阶段不再使用样本加权。每个 batch 携带原始 `sex_batch`，从真实标签为 1 的样本中提取男女预测概率，计算高斯核 MMD²：

```text
MMD² = 男性组内核均值 + 女性组内核均值 - 2 × 男女组间核均值
训练总损失 = 普通 BCE + mmd_weight × MMD²
```

当前 `sigma=0.2` 控制核宽度，`mmd_weight=0.1` 控制惩罚强度；都只是当前实验配置。`calculate_mmd` 使用包含对角项的有偏估计，某批缺少任一组正例时返回零。MMD 保留在计算图中，与 BCE 一起反向传播。它借鉴了 Google MinDiff 对齐分布的思路，但没有调用 TensorFlow MinDiff，也没有完全复刻其辅助数据批次流程。概率分布差异缩小，不保证固定 0.5 阈值下的召回率差距必然缩小。

当前实现应称为“借鉴 MinDiff 思路的 PyTorch MMD 公平性微调”，不是 Google MinDiff 的完整复现。MMD 是衡量分布差异的一种方法，不能与 MinDiff 整套训练方法或工具直接画等号。以下比较针对本目录的两个具体实现：

| 对比 | `google_fairness_mindiff.py` | `mmd_torch_11f.py` |
| --- | --- | --- |
| 实现方式 | TensorFlow 的 `MinDiffModel` 和 `MMDLoss` | 自己编写 PyTorch `calculate_mmd`，加入训练损失 |
| 起始模型 | 本脚本刚训练好的基础模型 | 已保存的加权微调模型 |
| 两组辅助样本 | 分别构造真实高收入男女的辅助批次 | 从当前普通训练 batch 中筛选真实高收入男女 |
| 缺少某组正例 | 辅助批次来自预先准备的两组数据 | 当前批次的 MMD 返回零 |
| 惩罚配置 | `loss_weight=1` | `mmd_weight=0.1`，高斯核 `sigma=0.2` |

两者共同使用分类损失与分布差异惩罚，但数据组织、起点和损失配置不同，训练效果不能视为等价。

三个训练文件的验证 Loss 都是普通 BCE，不含样本加权或 MMD，便于比较分类表现。验证平均 Loss 按“每批平均损失 × 该批人数”累加，再除以总人数；不能每批覆盖累计值后再除以总人数。Accuracy、AUC 每轮重置后按批累计。

### 2026-10-18 讨论与实验记录

Loss 越低通常表示分类损失越小；Accuracy 越高表示当前阈值下分类正确比例越高；AUC 越高表示模型整体排序能力越好。整体指标不能替代分组公平性指标。本次重点是减少女性漏判、缩小男女召回率差距，同时保留整体预测能力并关注误报代价，而不是单纯追求 Loss 低于 0.4。

验证 Loss 在约 0.41 附近进入平台期，不等于已经过拟合。典型过拟合表现为训练损失继续降低、验证表现持续恶化；当前仅有验证日志，不能完整判断训练与验证的差距。此次 MMD 验证 Loss 略降，没有显示持续恶化趋势。训练目标包含 MMD，而打印的验证 Loss 只有 BCE，因此 BCE 不下降也不能单独说明公平性干预无效。

## 数据与预测任务

两个脚本均读取根目录下的 [acsincome_raw_2018.csv](../data/acsincome_raw_2018.csv)。路径根据脚本所在位置计算，不依赖终端的当前目录。

任务是预测个人年收入是否超过 50,000 美元。代码将 `PINCP` 收入列转换为二元标签：

- `PINCP > 50000`：标签为 `1`，表示高收入。
- `PINCP <= 50000`：标签为 `0`。

其余 11 列均作为模型输入，包括 `SEX` 性别列。公平性评估也使用该列分组：`1.0` 为男性（Male），`2.0` 为女性（Female）。分组分析时才将数值转换为可读名称，训练输入保留原始数值。

## 基础模型

模型使用 TensorFlow / Keras 构建，结构为：

```text
11 个输入特征 → 归一化 → Dense(64, ReLU) → Dense(32, ReLU) → Dense(1, Sigmoid)
```

最后一个节点输出收入超过 50,000 美元的预测概率。训练使用 Adam 优化器和二元交叉熵损失，监控准确率与 AUC。

当前参数：

| 参数 | 值 |
| --- | --- |
| 训练集 / 测试集 | 80% / 20% |
| 训练集抽样随机种子 | `200` |
| 训练批大小 | `100` |
| 基础模型训练轮数 | `10` |

训练结束后，脚本在测试集上评估整体表现，生成预测概率，并通过 TensorFlow Model Analysis（TFMA）计算整体和按性别分组的指标。

## MinDiff 训练

`google_fairness_mindiff.py` 包含完整的基础模型流程，可以单独运行，不需要先运行基础模型脚本，也不读取已保存的模型。

基础模型训练完成后，脚本从训练集中分别选出真实标签为 `1` 的女性和男性样本，作为 MinDiff 的两组辅助数据。它们各自按 `50` 条组成批次，不足一批的部分被舍弃。

代码使用 `MinDiffModel` 包装已经训练过的基础模型，采用 `MMDLoss`、`loss_weight=1`，再训练 `10` 轮。训练同时考虑收入分类损失和两组正例的预测分布差异，目标是缓解与召回率差异有关的偏差。

这里的辅助样本只包含真实高收入者，因此该训练目标不保证准确率、精确率、召回率和假阳性率都同时接近，也不保证每次训练都有相同的改善结果。

## 报告怎么看

两个 HTML 报告均提供 `0.10` 到 `0.90`、步长为 `0.05` 的阈值滑块，默认阈值为 `0.50`。预测概率大于或等于阈值时，报告将该样本判为高收入。

| 指标 | 在本练习中的含义 |
| --- | --- |
| Accuracy（准确率） | 该组所有样本中，收入类别判断正确的比例 |
| Precision（精确率） | 该组被预测为高收入的人中，实际高收入者的比例 |
| Recall（召回率） | 该组实际高收入者中，被模型识别出来的比例 |
| FPR（假阳性率） | 该组实际非高收入者中，被误判为高收入的比例 |

基础模型报告还显示男女各自的混淆矩阵，包含正确判断的低收入者（TN）、误判为高收入者（FP）、漏判的高收入者（FN）以及正确识别的高收入者（TP）。MinDiff 报告仅显示指标柱状图。

滑块只是用已有预测概率重新计算指标，不会重新训练模型。报告中某项指标的分母为零时，当前代码将该指标显示为 `0`。

## 运行方式

以下命令用于运行两个 Google 练习脚本，已运行的环境为 macOS。仓库不包含开发者本机的 Conda 环境，目前也未提供可直接复现 Python 环境的配置文件。运行前需自行准备兼容的 Python 环境及下文列出的依赖。

在仓库根目录执行。下面的 `machine_learning` 仅为开发者本机的环境名，请替换为自己已配置好的 Conda 环境名；如果使用其他环境管理方式，先按对应方式激活环境，再执行 Python 命令：

```shell
conda activate machine_learning
python 公平性/google_fairness_baseline.py
```

运行包含 MinDiff 的完整练习：

```shell
python 公平性/google_fairness_mindiff.py
```

脚本使用 NumPy、pandas、Plotly、TensorFlow、TensorFlow Model Analysis、TensorFlow Model Remediation 和 protobuf。基础模型脚本也导入了 Model Remediation。MinDiff 脚本在导入 TensorFlow 前设置 `TF_USE_LEGACY_KERAS=1`，使用旧版 Keras 接口；运行环境需要具备对应的兼容依赖。具体兼容版本未在本目录锁定。

每次运行都会重新训练并覆盖对应的 HTML 报告，然后尝试在浏览器中打开。MinDiff 脚本会先覆盖 `fairness_report.html`，再生成 `min_diff_fairness_report.html`。只查看仓库已有报告时，直接用浏览器打开 HTML 文件即可，无需运行训练脚本。

## 当前实现说明

- 归一化层目前在划分训练集和测试集之前，使用全部样本计算统计量，因此测试集信息参与了预处理，评估结果存在这一限制。
- 代码只固定了训练集抽样种子，没有固定全部训练随机性；两个脚本分别运行时，基础模型结果可能不同。比较 MinDiff 前后表现时，可查看 MinDiff 脚本在同一次运行中生成的两份报告。
- 当前脚本不保存训练后的模型，HTML 报告展示的是生成报告时的评估结果。
