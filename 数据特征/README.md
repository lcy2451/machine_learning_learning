# 数据特征

许多数据集以表格（网格）的形式存储数据，例如使用逗号分隔值（CSV）格式，或者直接存储在电子表格或数据库表中。

表格是一种直观的机器学习模型输入格式。你可以将表格中的每一行视为一个样本（Example），将每一列视为一个潜在的特征（Feature）或标签（Label）。

不过，数据集也可以来源于其他格式，例如日志文件（Log Files）和协议缓冲区（Protocol Buffers）。

无论数据采用何种格式，机器学习模型的表现都取决于其训练数据的质量。

## 数据类型
数据集可以包含多种不同的数据类型，包括但不限于以下几种：
- 数值数据
- 分类数据
- 人类语言 （目前还没有接触过）
- 多媒体（例如图像、视频和音频文件）
- 来自其他机器学习系统的输出
- 嵌入向量（什么来着）

## 数据量
根据一条粗略的经验法则，**用于训练模型的样本数量至少应为模型可训练参数数量的 10 倍至 100 倍**。然而，优秀的模型通常需要使用**远多于这一数量的样本**进行训练。
**使用特征较少的大型数据集训练的模型，通常比使用特征较多的小型数据集训练的模型表现更好。** 谷歌过去曾多次通过使用大型数据集训练简单模型，取得了非常出色的效果。
==不同的机器学习任务可能需要数量差异巨大的训练样本，才能构建出实用的模型。对于一些相对简单的问题，几十个样本可能就足够了；而对于另一些问题，即使有一万亿个样本，也可能仍然不够。==

如果对一个已经使用大量\*\*具有相同数据结构（Schema）\*\*的数据训练过的现有模型进行调整(==微调==)，那么即使只使用较小的数据集，也有可能获得良好的效果。

## 数据的质量和可靠性
人人都更倾向于高质量而非低质量，但“质量”本身是一个模糊的概念，可以有多种不同的定义。
>高质量的数据集有助于模型实现其目标，而低质量的数据集则会阻碍模型实现目标。

高质量的数据集通常也具有较高的可靠性。**可靠性（Reliability** 是指数据值得信赖的程度。与使用不可靠数据训练的模型相比，使用可靠数据集训练的模型更有可能产生有用的预测结果。
在衡量可靠性时，您必须确定：
- **标签错误有多普遍？** 例如，如果数据是由人工标注的，那么标注人员出现错误的频率有多高？
- **你的特征数据是否存在噪声（Noise）？** 也就是说，特征值中是否包含误差？需要认识到，你不可能完全消除数据集中的所有噪声。一定程度的噪声是正常的。例如，即使测量的是同一个位置，GPS 的测量结果也总会随着时间推移而略有波动。
- **数据是否根据你要解决的问题进行了适当的筛选？** 例如，你的数据集是否应该包含自动化程序（Bot）发起的搜索查询？如果你正在构建一个垃圾信息检测系统，那么答案很可能是肯定的。然而，如果你的目标是改善真人用户的搜索结果，那么答案就是否定的。

## 以下是导致数据集中数据不可靠的常见原因：
- 遗漏值（Omitted values）：例如，某人忘记填写房屋的房龄。
- 重复样本（Duplicate examples）：例如，某台服务器误将相同的日志记录上传了两次。
- 错误的标签（Bad labels）：例如，某人错误地将一张橡树的图片标注为枫树。
- 存在问题的数据片段（Bad sections of data）：例如，某个特征的数据通常非常可靠，但某一天由于网络不断崩溃，导致当天的数据出现了问题。

>任何足够大或足够多样化的数据集几乎肯定包含超出数据模式或单元测试范围的异常值 。如何处理异常值是机器学习的重要组成部分。

## 完整示例与不完整示例
不要使用不完整的样本来训练模型。相反，应该通过以下方法之一修复或删除这些不完整的样本：
- 删除不完整的示例。
- 填补缺失值；也就是说，通过对缺失值进行合理的猜测，将不完整的示例转换为完整的示例。


如果数据集中有足够多的完整样本，可以用来训练出一个实用的模型，那么可以考虑删除不完整的样本。

同样，如果只有某个特征存在大量缺失值，而且该特征可能对模型的帮助不大，那么可以考虑将其从模型的输入特征中删除，并观察删除后模型性能下降了多少。

如果删除该特征后，模型的表现与之前相同或几乎没有差别，那就再好不过了。

反过来，如果没有足够多的完整样本来训练一个实用的模型，那么可以考虑对缺失值进行插补（Imputation）。 

删除无用或冗余的样本是可以的，但删除重要样本则不可取。遗憾的是，区分无用样本和有用样本可能并不容易。

如果无法确定应该删除不完整的样本，还是对缺失值进行插补，可以考虑构建两个数据集：一个通过删除不完整的样本得到，另一个通过插补缺失值获得。

然后，比较使用这两个数据集训练的模型，判断哪一个模型表现更好。

>巧妙的算法可以很好地填补缺失值；然而，填补值很少能与实际值一样好。因此，一个好的数据集能够告诉模型哪些值是填补的，哪些值是实际的。一种方法是在数据集中添加一个额外的布尔列，用于指示特定特征的值是否是填补的。例如，给定一个名为 temperature 的特征， 您可以添加一个名为类似这样的额外布尔特性 temperature_is_imputed 。然后，在训练过程中，模型可能会逐渐学会更信任包含特征 temperature 的插补值的示例，而不是包含实际（非插补）值的示例。

> **插补（Imputation**是指根据合理的推断生成数据，而不是随意生成随机或具有误导性的数据。需要注意的是：合理的插补可以改善模型的表现，而不恰当的插补则可能损害模型的表现。

一种常见的插补方法是使用均值或中位数来填补缺失值。因此，当使用 **Z 分数（Z-scores）**表示数值特征时，通常会使用 0 作为插补值（因为 Z 分数的均值通常为 0）。
